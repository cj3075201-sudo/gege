실행 순서:
1. 새 검사에서 고양이 타입 부재 실패를 확인한다.
2. 런타임 상태 기계와 기존 재질·기본 도형 프리팹 생성기를 작성한다. Unity API로 프리팹/GUID를 생성한다.
3. 실제 batchmode Play에서 무음식/해금/시작/막기/회피/명중/승패/도주/추종/음식복구/구역/비활성/탈출을 확인하고, 프리팹 스크린샷을 렌더해 직접 읽는다.
4. DevToolsStatsChecks, ZoneRulesVerification, HazardZoneChecks, HazardGateChecks와 새 검사를 실행하고 error CS 0건을 확인한다.
5. 자체 diff 검토 후 담당 파일만 커밋한다. 외부 보고서 맨 위에 커밋·kind GUID·후보 조건·25/6 수를 기록한다.

### 통합 경계와 HTML 차이

- 설정/후보 자산은 수정하지 않았다. 메인이 kind(type cat, role Trigger, unlockDay2, poolSize31), 후보(큰길25/골목6 기준)를 등록해야 실제 게임 씬에서 조우한다. count는 지도 전체 기준이며 열린 길 비율/배치는 기존 planner 담당이다.
- 동료의 다른 함정 대신 소모는 공개 API 부재로 제외했다(의뢰가 허용한 제외). 동료 추종·70초 종료·배달 종료 정리는 구현했다. 타이어 TryActivate는 소모·무력화가 아니라 실제 공격을 시작하므로 대신 소모 경로로 오용하지 않았다.
- 잽 음식 보존은 TryContactCrash로 처리한다. 따라서 잽은 기존 HazardHit 기반 통계 및 공통 날림 높이/거리 배율을 통과하지 않는다. 잽 자체 직렬화 속도는 F1에서 조절된다. 통합 시 HazardPlanner.OnRiderHazardHit에서 CatBoxerHazard.KeepsFoodOnCurrentHit를 검사해 낙하를 건너뛴 뒤, 잽도 TryHazardCrash로 통일하면 된다.
- 같은 함정의 공중 연속 피격을 기존 RiderMotor API가 거부하면 피격 횟수도 늘리지 않는다. HTML은 공중/다운 상태에도 연속 발사를 허용한다. 해당 공통 사고 정책 파일은 다른 담당 소유이므로 수정하지 않았다.
- 소리 지르기(Q) 3초 멈칫·예고 자세·고리 크기/색·한글 문구/체력 표시는 구현했다. juice3d의 합성 효과음/파티클 전체를 새로 이식하지 않았다.
- 음식 없이 고양이는 숨긴다(의뢰의 미출현 시험 기준). HTML은 활성 자리의 수령 전 잠든 모형을 표시한다. 지도/콜 UI에서는 기존 Unity 입력 경계에 맞춰 공격 진행을 멈춘다.
- 일반 손실/음식 회복은 기존 HazardPlanner/DroppedFood를 그대로 사용한다. 전체 게임 씬 자연 조우, 실제 확장 맵의 모든 벽/경사 착지, 오디오 청취, 무작위 22초 대결 전체 밸런스는 이 시험에서 확인하지 않았다.
